# Cubby — Search Architecture

> Step 2 deliverable.

---

## Search strategy (MVP)

**Local keyword search only.** Drift FTS5 (SQLite full-text search) handles all search for MVP. No external search service. Works offline. Zero cost.

Semantic search (pgvector + embeddings) is deferred to post-MVP when data shows keyword search is insufficient.

---

## FTS5 index

Indexed fields per FamilyItem:
- `title` (weight: 10)
- `document_type` (weight: 5) — human-readable label
- `extracted_text` — flattened text from `extracted_fields` JSON (weight: 3)
- `notes` (weight: 2)
- `tags` — flattened tag array (weight: 2)
- `member_names` — denormalized names of linked family members (weight: 8)

Index updated on: item creation, item confirmation, item edit, member name change.

## Query pipeline (SearchOrchestrator)

```
User query: "Arjun's visa"
  │
  ▼
QueryParser
  - Extract entity references: "Arjun" → match to FamilyMember
  - Extract type hints: "visa" → DocumentType.visa
  - Extract date references: "last year" → date range filter
  - Remaining keywords: search terms
  │
  ▼
FTS5 Search
  - If entity found: filter by member_id via FamilyItemLink
  - If type found: filter by document_type
  - If date range: filter by event_date or created_at
  - FTS5 MATCH on remaining keywords
  - ORDER BY rank (BM25)
  │
  ▼
Result formatting
  - Return top 20 results
  - Each result: { item, rank, snippet, linked_members }
  - Snippet: relevant text extract with query terms highlighted
```

---

## Entity-aware search

The QueryParser maintains a local lookup of family member names (including nicknames and pet names). Before running FTS5, it checks if any query tokens match a family member name. If so, results are scoped to that member's linked items.

```
"Buddy vaccination" → entity: Buddy (pet), type: vaccination
  → SELECT from family_items
    JOIN family_item_links ON member_id = Buddy.id
    WHERE document_type = 'petVaccination' OR document_type = 'vaccinationRecord'
    AND MATCH(search_index, 'vaccination')
```

---

## Search UI patterns

- **Home screen:** Search bar at top. Tapping opens full search with keyboard.
- **Person detail:** Search scoped to that person's items.
- **Global search:** All items, all members. Entity chips as filters.
- **Recent searches:** Stored locally, max 10.
- **No results:** "No items found. Try adding more documents to your vault."

---

## Future: semantic search (post-MVP)

When added, the pipeline becomes:
```
Query → QueryParser → [Keyword FTS5] + [Semantic pgvector] → Merge & Re-rank → Results
```

Embeddings generated by EmbeddingOrchestrator on item confirmation. Stored in pgvector column on Supabase. Semantic search handles intent-based queries ("documents expiring soon") that keyword search misses.
